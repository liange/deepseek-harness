# Capability Execution — Implementation

How shell, subprocess, terminal, filesystem, LSP, code-runtime, sandbox, E2B, and workspace internals work. See [subsystems/shell.md](../subsystems/shell.md), [subsystems/subprocess.md](../subsystems/subprocess.md), [subsystems/terminal.md](../subsystems/terminal.md), [subsystems/filesystem.md](../subsystems/filesystem.md), [subsystems/lsp.md](../subsystems/lsp.md), [subsystems/code-runtime.md](../subsystems/code-runtime.md), [subsystems/sandbox.md](../subsystems/sandbox.md), and [subsystems/workspace.md](../subsystems/workspace.md) for type definitions.

## Shell execution (`dsh-shell`)

The `ShellExecutor` abstract service defines the `ctx.shell` capability seam. `resolve(request)` fills defaults and produces a `ShellExecSpec`; `run` rejects only for infrastructure failures (nonzero exit, timeout, and abort all resolve with a result); `start` returns a `ShellProcess` whose `readOutput()` is incremental and consuming, `done` never rejects, and `kill()` is idempotent. `timedOut`/`aborted` are mutually exclusive (first-cause classification). `dsh-shell-env` owns the `ctx.shellEnv` registry of trusted `DSH_*` variables injected into every model shell call. The ambient executor discards host `DSH_*` before the snapshot merges last, so stale host values can never leak in.

`dsh-bash-local` runs commands as `bash -c` via `ctx.subprocess`. `resolve()` clamps `timeoutMs` (default 120s, cap 600s), defaults `workdir`, and carries a stdout byte budget. `spawnSpec()` layers env as `ENV_OVERRIDES → spec.env → spec.dshEnv`. `dsh-bash-sandbox` extends it: wraps argv through `ctx.sandbox.confine()`, classifies runner-spawn failure (`SandboxUnavailableError`) before runner-failure stderr rules before denial signatures, and keeps a per-process `processFacts` map. `dsh-pwsh-local` mirrors bash-local with PowerShell: each command is one argv element after `-Command`, an `ENCODING_PREAMBLE` sets UTF-8 output, and `resolvePwshPath()` probes PowerShell 7 then Windows PowerShell 5.1. `dsh-pwsh-sandbox` mirrors bash-sandbox identically.

`dsh-tool-bash` is the model-facing Consumer: foreground calls run synchronously; `run_in_background` registers a `ctx.jobs` task driving a `ShellProcess` handle. Sandbox escalation is approved through `ctx.approval` before execution. `dsh-tool-bash-persistent` uses the PTY seam: one long-lived shell per agent, commands wrapped as `printf start; eval -- <command>; printf end:$status` on one line, with a scrollback-based end-marker detection loop. `dsh-tool-pwsh` mirrors tool-bash with PowerShell-dialect contract.

## Subprocess execution (`dsh-subprocess`, `dsh-subprocess-local`)

`SubprocessRuntime` is the abstract Service Definition: `spawn` applies no defaults, every disposition is explicit. `scrubbedParentEnv()` is the shared scrub: parent env minus names matching `SENSITIVE_ENV_PATTERN` minus `DSH_*`. `dsh-subprocess-local` is the host-local backend. `spawnSubprocess()` uses POSIX `detached: true` (own process group). `OutputCollector` keeps an in-memory tail capped at `maxBytes`; on first overflow it opens a private `0700`-dir spill file with `'wx'` open and replays prior chunks. `treeAlive()` polls `kill(-pid, 0)` plus Linux `/proc` member probes. `terminate()` starts the single `observeTreeExit` observer, sends SIGTERM, arms a ref'd `graceMs` SIGKILL timer, and awaits whole-tree exit. `done` settles bounded by the same grace if a descendant holds pipes.

## Terminal (`dsh-terminal`, `dsh-terminal-bash`)

`TerminalSessionService` owns session ids, publication, authorization, and cleanup. `spawn(owner, {type, name?, cwd?})` mints ids `pty-N`, reserves the owner-local name, and tracks a `PendingSpawn` with an `AbortController`. Publication is all-or-nothing: on failure the unpublished session is closed (rollback). All operations require the exact owner (`expectOwned`). `dsh-terminal-bash` is the PTY backend: spawns a controlled bash prompt with `PS1='dsh> '` and a `PROMPT_COMMAND` that emits a private OSC marker before each prompt. Output streams through a `TerminalSanitizer` (strips CSI/OSC, tracks the owned marker) into line+byte bounded scrollback. Readiness: after `terminal.write`, the `pollReadiness` loop settles on `stdin_read` when the owned prompt plus shell foreground pgid are seen after an idle window, or `inferred_idle` after `idleSilenceMs`. `dsh-tool-terminal` exposes six model-facing tools (`terminal_open/send/read/signal/close/list`) with background sends registered as `ctx.jobs` tasks.

## Filesystem (`dsh-fs`, `dsh-fs-local`, `dsh-fs-sandbox`)

`FileSystem` is the abstract Service Definition: `resolve` returns a stable `FsTarget` with alias-invariant `targetKey`; `versionOf` = `dev:ino:size:mtimeNs:ctimeNs`. `dsh-fs-local` resolves targets via realpath: for missing targets it walks up realpathing the nearest existing ancestor and re-appends the missing suffix. Mutations serialize per `targetKey` in a FIFO promise chain (`withLock`). `writeText` uses `writeFileAtomic`: a sibling `.name.pid.uuid.tmpdir` dir chmod `0700`, temp file opened `'wx'`/`0600`, content written and fsynced, then `rename` over the target. `editText` normalizes CRLF→LF, detects the dominant ending, applies `applyLiteralEdit` (counts occurrences: 0 → `FS_EDIT_NOT_FOUND`, >1 without replaceAll → `FS_AMBIGUOUS_EDIT`), and restores line endings on write-back. `dsh-fs-sandbox` extends `LocalFileSystem` with a per-call sandbox fence on mutations: `read-only` throws `FS_SANDBOX_DENIED`; `workspace-write` re-resolves the target and requires containment under `writableRoots` (workspace root + `/tmp` + platform temp). `dsh-fs-observation-policy` records every authoritative observation per session and derives mutation guards: `present` → `replaceIfVersion`, `absent` → `createIfAbsent`.

`dsh-tool-fs` provides `read`/`write`/`edit`/`read_image` tools. `read` does one stat for type routing and size, then streams or windows. `write`/`edit` resolve sandbox policy, take the single-slot `fs/write-intent` or `fs/edit-intent` waterfall, then call the provider. `dsh-tool-fs-search` runs the packaged ripgrep binary through `ctx.subprocess.spawn` — never `ctx.shell`. `dsh-tool-str-replace-editor` provides `view`/`create`/`str_replace`/`insert` commands over `ctx.fs`.

## LSP (`dsh-lsp`, `dsh-lsp-stdio`)

`Lsp` is the Service Definition with four read-only operations (`goToDefinition`, `findReferences`, `goToImplementation`, `hover`). `registerProvider` validates everything before mutating (all-or-nothing): non-empty id, extension map, language ids, intra- and cross-provider conflict checks. `dsh-lsp-stdio` resolves every executable through `ctx.subprocess.resolveExecutable` before publishing any provider. `LocalLspProvider.query` canonicalizes the workspace via `ctx.fs`, then enqueues the full read→(get-or-create instance)→query lifecycle per workspace key. `LspInstance.initialize` negotiates position encoding (utf-16 only). Each query is `didOpen → request → didClose`. Transport failure disposes the instance and retries once on a replacement. `LspConnection` frames via Content-Length codec (header ≤64KiB, body ≤`maxMessageBytes`). `dsh-tool-lsp` converts 1-based UTF-16 cursor coordinates to the seam's zero-based positions.

## Code runtime (`dsh-code-runtime`, `dsh-code-runtime-worker-thread`)

`CodeRuntime` defines the abstract seam: one model-written program against host async bindings. `dsh-code-runtime-worker-thread` is the worker-thread backend. `run()` type-strips the program via `node:module.stripTypeScriptTypes` inside an `async function __dsh_program__() {}` wrapper. A fresh worker is spawned with `env:{}`, `execArgv:[]`, and heap `resourceLimits`. In-worker: `runWorkerMain` builds null-prototype namespaces (async bridge over MessagePort), a five-method console shim, and patches `process.stdout/stderr.write` into an ordered `LogBuffer`. Budgets: eventLoopUtilization busy-time poll at 25ms cadence → `timeout`, plus a wall-clock backstop. The host-side `parseWorkerMessage` re-validates every inbound frame field-by-field (hostile peer). `OutputLedger` enforces the combined JSON-byte cap. Exactly one outcome wins; every path drains pipes, terminates, and awaits the worker.

## Sandbox (`dsh-sandbox`, `dsh-sandbox-local`, `dsh-sandbox-policy`)

`SandboxProvider` is the abstract seam: `SandboxMode = 'read-only' | 'workspace-write' | 'danger-full-access'`. Policy is carried per call (two consumers may confine under different policies simultaneously). `dsh-sandbox-policy` owns `ctx.sandboxPolicy`: `resolve(request)` precedence is explicit approved mode > session's last `sandbox/mode` event > deployment default. The per-session override is the session log: `setSandboxMode` appends a `sandbox/mode` event; `effectiveSandboxMode` is a pure backward fold. `dsh-sandbox-local` selects the platform runner chain: Linux bwrap→Landlock, macOS Seatbelt, Windows the ACL restricted-token runner. Multi-rung chains are arbitrated by functional probes cached once. `confine()` emits `[runner, ...profileArgs(policy), '--', ...argv]`. On the Windows ACL rung, `AclSandbox` materializes a standing workspace write SID grant (deterministic from sha256) and a per-session private temp SID, creates a restricted token with the capability SIDs, and merges a full-access ACE into the token DEFAULT DACL so grandchild pipes survive.

## E2B remote sandbox (`dsh-e2b`, `dsh-fs-e2b`, `dsh-subprocess-e2b`)

`dsh-e2b` owns the shared E2B SDK sandbox handle. `open()` creates the sandbox, provisions `cwd` and the private `runtimeRoot`, and verifies it is a real directory. `dsh-fs-e2b` implements `ctx.fs` over the remote sandbox: `resolve` computes `targetKey` through a remote `realpath -mz | base64` command; mutations serialize per key and publish atomically via a private staging dir with SDK `rename`. `dsh-subprocess-e2b` implements `ctx.subprocess`: each handle runs a generated control script via `sandbox.commands.run` with `background: true`. The command text resolves bootstrap tools via `command -v`, writes pgid and exit code to state files, and tees each output stream through `tee > head -c spillCap > file | node -e <base64 encoder>`. Output is base64-framed over newline-delimited transport with a terminal `!dsh-e2b-output-complete!` frame.

## Workspace (`dsh-workspace`)

`WorkspaceRegistry` stores workspace entities in a `dsh-storage-domain` domain (version 2). `[Service.init]` opens the domain, recovers pending mutation markers, validates stored state (unique paths, one-owner-per-session, order↔table bijection), then runs a one-time bootstrap: groups persisted session headers by canonicalized `header.cwd`, newest-first, and assigns unaccounted members to existing workspaces. All mutations run on one operation chain. `createCanonical` is a pending-marker double-write with rollback on failure. `WorkspaceEntity` holds a private record snapshot swapped after each durable `mutate`; its `sessionIds` getter filters members whose canonical cwd differs from the workspace path.
