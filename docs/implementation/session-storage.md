# Session and Storage — Implementation

See [subsystems/session.md](../subsystems/session.md), [subsystems/persistence.md](../subsystems/persistence.md), [subsystems/session-projection.md](../subsystems/session-projection.md), [subsystems/session-telemetry.md](../subsystems/session-telemetry.md), [subsystems/session-title.md](../subsystems/session-title.md), [subsystems/session-query.md](../subsystems/session-query.md), and [subsystems/storage.md](../subsystems/storage.md) for type definitions.

## Session persistence (`dsh-session-persistence`)

`PersistenceCoordinator` is the shared write-path orchestration. Each session id has a promise-chain serializer so writes never interleave. `SessionWriteBehind` buffers events with a fixed `maxDelayMs` deadline timer; failed batches are prepended back and pause automatic drain. `SessionPreparations` manages per-id entries with `loading | ready | committing | reserved` phases, shared in-flight reads, and LRU-capped ready entries. Crash recovery: `prepareCore` reads the backend's `StoredPrefix`, synthesizes `interruptedTurnClosers` for a complete interrupted turn, and discards only torn tails. `commitPrepared` makes repairs durable then forces a reload. Revision-stability retry loops back cold reads. Legacy migration refuses retired event types (`request/header-delta`, `mode/set`, `fallback`) and upgrades pre-identity message events.

**JSONL backend** (`dsh-session-persistence-jsonl`): One append-only artifact per session at `root/<project>/<encoded-id>/session.jsonl[.zstd]`. `encodeSegment` maps every unsafe UTF-16 unit to `~XXXX` (injective, traversal-proof). Append = open `a` → stat → writeFile → fsync; partial failure truncates back to pre-write size. Materialization (POSIX) does mkdir + dir-fsync chain, fsync'd temp, publish via `link+unlink` (EEXIST fails second process), fsync parent. Each append batch is one independently decodable checksummed zstd frame. Crash recovery: `scanZstdFrames` finds complete frames plus the torn start; the torn final frame is prefix-decoded to salvage complete records. `commitRepair` = truncate+fsync then append recovered+closers.

**SQLite backend** (`dsh-session-persistence-sqlite`): Schema `SCHEMA_VERSION = 15` (monotonic; non-current rejects, no migration) guarded by `application_id 0x44534850`. STRICT tables: `persistence_state` (singleton store UUID), `sessions` (header + `incarnation` UUID + `revision` counter), `events` (PK session_id+seq; `data` JSON text; nullable `source_event_seqs` and `surface_op` JSON). `appendBatch` = one BEGIN/COMMIT: insert-or-replace sessions row, insert events, `revision+1`. `commitRepair` = one transaction DELETE `seq>=tornMarker` + insert closers. Torn-tail semantics match JSONL: `scanRows` tolerates seq gaps after the last `turn/end` but throws on gaps within the committed prefix.

## Session projection (`dsh-session-projection`, `dsh-session-projection-cache`)

`SessionProjectionMap` is the Service Definition. A projection unit is `{key, schema (zod), init(), apply(state, event), view(state), stateVersion}` — pure, synchronous, plain-JSON. The registry subscribes `session/event` once and `drive()`s every unit per event. Same-reference return produces zero downstream work. Cells are per-Session WeakMap entries folded lazily from the in-memory log. `register()` is a refcounted effect. `dsh-session-projection-cache` stores durable checkpoints on the `session_projcache` storage domain (v3). Write-behind per live session counts events; triggers include count ≥ `writeEveryEvents`, interval timer, and mandatory points (`turn/end`, `session/disposed`). The cache always lags, never leads the log. Cold ladder: `cachedSnapshot` views rows matching the session's lifecycle identity; identity mismatch, shrink, or version mismatch → one full re-read from seq 0.

`dsh-session-stats` registers the `sessionStats` projection unit: whole-log turn/step counts and wall times, immune to paging and compaction. `step/end` (emitted once per entered step in a `finally`) is the counted step. `tool/result` matches by `callId` with an `Object.hasOwn` guard.

## Session telemetry (`dsh-session-telemetry`, `dsh-session-telemetry-otel`)

`SessionTelemetry` defines the logical record vocabulary and backend (sink) contract. The coordinator listens `session/created` (adopt = replay through projection from the handoff cursor), `session/event`, and `session/disposed`. `handoffCursor` is a module-scope WeakMap keyed by Session — the cursor advances only after `emit` accepts. Redaction is the `session-telemetry/record` waterfall. `dsh-session-telemetry-otel` composes the OTel JS SDK with `LoggerProvider` + `BatchLogRecordProcessor` + OTLP/HTTP exporter. Modes: `FULL | FEEDBACK_ONLY | DISABLED` (default DISABLED). DISABLED builds no SDK state. FULL composes a live coordinator; FEEDBACK_ONLY composes an on-demand coordinator plus a custody check (`session.events[event.seq] === event`). `shutdown()` races provider shutdown against a deadline.

## Session titles (`dsh-session-title`, `dsh-session-title-llm`)

Titles are log-only `session/title` events carrying `{title, messageSeqs, source}`. `get()` = `foldSessionTitle` (last-wins). `rename()` normalizes (strips control chars, collapses whitespace, UTF-8 byte budget), rejects empty, and pins the title while superseding in-flight generation. Automatic cadence uses per-session `SessionTitleWorkState`: eligible `user/message` schedules generation; work starts only after the exact main-request route is logged. One active provider call per session: `supersede` aborts the stale controller, `assertCurrent` refuses completion from a dead revision. `dsh-session-title-llm` is the shared framing library: `generateSessionTitleWithLlm` frames messages as one JSON document, byte-checks against `maxInputBytes`, resolves the route, applies a deadline, appends a log-only `session/title-llm-request` event, and streams through `ctx.llm.stream`. `dsh-session-title-first-prompt-llm` and `dsh-session-title-all-prompts-llm` are thin provider plugins differing only in message selection cadence.

## Session query (`dsh-session-query`, `dsh-session-query-sqlite`)

`SessionQuery` is the Service Definition providing combined session-history reads, traces, filters, and full-text search. `SessionCorpus` binds persistence optionally; `listSessions` merges persisted headers with live sessions (live wins). `load()` prefers a detached live snapshot and re-checks attach races. `tracing.analyzeEventLog` runs one canonical `foldSurface` per log: events classified `current | shadowed | log-only`, replacement chains walked via `sourceEventSeqs`. `traceSession` walks `parentSession` ancestry with cycle detection.

`dsh-session-query-sqlite` is the concrete backend with FTS5 over a live-preferred corpus. FTS schema v8 / application id `0x44534851`; version mismatches DROP all tables and reset in place. Every search is serialized, then reconciled: a two-attempt stable observation (before/after `listSnapshots` and live-id set must match), then a diff of indexed rows in one `BEGIN IMMEDIATE` transaction. Query CTE unions persisted docs with live docs. FTS5 `highlight()` uses private-use markers; ranking: match_count desc, document_length asc, time desc, seq desc. Cursors are base64url `{version, instance, scope, fingerprint, generation, offset}`. Queries are double-quote-escaped single phrases — FTS syntax inert. `dsh-tool-session-query` provides five workspace-authorized tools; authorization is enforced per observed header, not per request.

## Domain-KV storage (`dsh-storage`, `dsh-storage-domain`)

`Storage` is the hub: named backend registry plus mounted data-form facilities. `dsh-storage-domain` provides `DomainFacility` (`ctx.storage.domain`): schema-validated, change-emitting KV domains. `defineDomain` validates names and version. `DomainImpl` holds authoritative in-memory maps with one write chain (`enqueue`): every write awaits backend durability first, then mutates memory, then emits `domain/changed`, so a rejected write leaves memory untouched. `close()`: reject new writes, drain the chain, close the unit, free the name.

`dsh-storage-json` stores one pretty-printed file per unit under a root. `writeAtomic`: temp file (`wx`, `0600`) → write → fsync → `rename` over the target. `dsh-storage-sqlite` stores one database file with shared tables: `units(name PK, version)`, `unit_globals`, and per-unit record tables `u_<unit>_<table>(key TEXT PK, value TEXT NOT NULL) STRICT`. Each primitive is a single SQL statement; the caller owns write ordering. `loadAll` builds null-prototype record objects so a `__proto__` key lands as an own property.
