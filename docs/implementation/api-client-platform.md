# API, Client, and Platform — Implementation

English | [中文](api-client-platform.zh.md)

How the Typert type-graph, JSON-RPC SDK, ACP server, API gateway, web server, client module system, UI slot composition, and infrastructure utilities work internally. See [subsystems/typert.md](../subsystems/typert.md), [subsystems/web-server.md](../subsystems/web-server.md), [subsystems/client-modules.md](../subsystems/client-modules.md), and [subsystems/invariants.md](../subsystems/invariants.md) for type definitions.

## Typert type-graph (`dsh-typert-generator`, `dsh-typert-loader`, `dsh-typert-registry`, `dsh-typert-protocol`)

The Typert system has four layers. `dsh-typert-protocol` defines the compiler-independent protocol: `@Remote`/`@RemoteScope` class-method decorators record markers in a `WeakMap` via `addInitializer`. `InvocationDescriptor` carries service, namespace, method, codec (strict Zod or SRC-JSON), and optional cancellation signal. `dsh-typert-generator` is the TypeScript compiler: `WorkspaceAnalyzer` parses aggregate tsconfigs per face, builds `ts.Program`s, and extracts Cordis services, events, and tagged Typert roots into `FaceModel`. `FaceModelEmitter.emit(package)` produces `typert.host` JS/d.ts artifacts with Zod v4 schemas. `typertPlugin` (tsdown plugin) lowers decorators via `ts.transpileModule` and writes artifacts in `writeBundle`. `dsh-typert-loader` automatically registers packages' `./typert` host-face artifacts: it scans Loader entries incrementally, reconciles dirty names via a microtask flush, and validates every manifest (package ownership, face, zod instances, invocation descriptors) before `ctx.typert.register()`. `dsh-typert-registry` is the runtime registry: `DescriptorStore` keeps entries by endpoint and id; `LocalStore` hosts the active composition's definitions; `RemoteStore` owns registrations in Cordis effects; `LookupStore` separates provider registration from resolver configuration; `ContextStore` has `registerHost`/`configureHost` and `registerClient`.

## JSON-RPC SDK (`dsh-sdk-protocol`, `dsh-sdk-server`, `dsh-sdk-client`)

`dsh-sdk-protocol` defines the wire protocol: newline-delimited JSON-RPC 2.0 over stdio. `JsonRpcLineTransport` accumulates UTF-8 via `StringDecoder`, splits on newlines, and correlates requests via a `pending` Map. Wire vocabulary: `InitializeParams/Result`, `SessionPromptParams/Result`, and four server→client notifications (`session.event`, `session.status`, `subagent.started`, `subagent.finished`). `dsh-sdk-server` implements `HarnessSdkJsonRpcServer`: constructor subscribes Cordis event streams and forwards them as notifications. `initialize` validates `maxTokens`, records cwd/provider/model, and mounts the DeepSeek provider fiber. `prompt` lazily creates the Agent+Session pair and `followup`s a user message. `shutdown` is a memoized async teardown. `dsh-sdk-client` is the low-level client: `HarnessClient` spawns the runtime directly, speaks ndjson JSON-RPC over stdio, and implements `initialize`/`prompt`/`shutdown`. Notifications fan out to `NotificationSubscription`s with queues and waiters. Teardown is a private ladder: stdin EOF → SIGTERM → SIGKILL, each tier racing exit against unref'd timers.

## ACP server (`dsh-acp`)

`dsh-acp` is an automation-only Agent Client Protocol server over JSON-RPC stdio. It uses `@agentclientprotocol/sdk`'s `AgentSideConnection`. Per-session `SessionRecord` holds the owned Agent, its exact disposer, the `outputTail` promise for ordered assistant delivery, and an inflight settlement record. Handlers: `initialize`, `session/new`, `prompt`, `cancel`. Rich content admission validates inline images against a four-type raster MIME whitelist and canonical RFC 4648 base64; failures are `AcpContentError` with `invalid`|`internal` categories. `turnEndToStopReason` maps completed→`end_turn`, max-tokens→`max_tokens`, interrupted→`cancelled`, everything else→`end_turn`.

## API gateway (`dsh-api-gateway`, `dsh-api-remotes`)

`TypertGatewayService` is the host-side dispatcher turning Typert Remote endpoints into live Cordis Service method calls over the Connection RPC carrier. `claimsEndpoint` accepts endpoints present in `ctx.typert.local` or claimed via SRC markers. `invoke` resolves the `InvocationDescriptor`, asserts exact wire args, decodes parameters, resolves lookup parameters and Context receivers, invokes via `Reflect.apply`, and validates the result. `dsh-api-remotes` is the Host BFF policy layer: `API_REMOTE_FORWARDED_EVENTS` lists forwarded events (compile-time `satisfies` gate). `createApiRemoteAgentResolver` reuses live Agents, resumes cold sessions once per identity, and configures Typert lookups and contexts. The client face mounts selected Host Remote contributions.

## Web server (`dsh-host-webserver`, `dsh-host-frontend-static`, `dsh-host-apiproxy`)

`WebServer` is a route-registration plugin: `node:http` server with exact, prefix, and upgrade maps, index taps, and one fallback seat. `register` throws on duplicates; `registerFallback` allows exactly one owner. Matching is exact first, then longest-prefix-wins. `dsh-host-frontend-static` claims the fallback seat: non-GET/HEAD answers 405; otherwise `serveStatic` resolves the target, rejects traversal outside distRoot with 403, and serves index.html for SPA routing on any miss. Each index render is `await ctx.webServer.applyIndexTaps(readFile(distIndex))` — the boot-manifest injection point. `dsh-host-apiproxy` provides the transport-agnostic API gateway: `createApiProxy` returns pure closures per domain. `toFetchHandler` compiles `UNARY_ROUTES` with zod-validated invoke closures. Business errors ride 200 + ServerResponse; HTTP status expresses only carrier failures.

## Client module system (`dsh-client-connection`, `dsh-client-modules`, `dsh-client-runtime`, `dsh-client-web`, `dsh-client-web-react`)

`dsh-client-connection` is the browser carrier: Host HTTP/WebSocket bridge with DNS-rebinding trust fence. `PRIVILEGED_METHODS` is loopback-pinned on trusted-host deployments. Client-side `ConnectionController` opens two SSE streams in a pull-mode pump, waits both `onOpen` plus `describe`, reconnects with jittered exponential backoff. `dsh-client-modules` is the dual-face module system: Host scans Loader entries for `dsh.client` packages and serves the browser plugin graph. `parseDshClient` validates platform, inject, and immediately fields. The composed graph is the single wire shape feeding both the injected `window.__DSH_BOOT__` boot manifest and the served graph. Client side: the shell kernel constructs `ClientModuleSystem` with static modules before Cordis exists.

`dsh-client-runtime` is the React-free object layer holding all business state. `apply` mounts `SlotRegistry`, builds `SessionRuntime` and `WorkspaceRuntime`, registers the agent Typert Context client binder, then starts the connection. The snapshot-store engine (`createSnapshotStore`, zustand/immer) produces bare observable sources with no hooks. `ConversationNodeDefinition` registry + keyed `conversation.chat.node` renderers drive deterministic replay by log seq. `dsh-client-web` is the shell library: `AppWebEntry.run()` two-stage — module face (parse `window.__DSH_BOOT__`, build `ClientModuleSystem`) then plugin face (render loading page, prefetch immediately tier, mount Loader, create one entry per plugin-view row, `loader.await()` + full fiber sweep). `dsh-client-web-react` provides render machinery: `bindSnapshotSelector` is the one hook constructor (`useSyncExternalStoreWithSelector`). `createSlotRenderer` takes the runtime SlotRegistry host face and installs per-entry renderSlot bindings cached in `WeakMap`.

## UI slot composition

Every ui-* package is one feature with `src/client/` browser half and a stub node half. Composition has one API: `ctx.slots.register({ name, children?, store?, inject?, locale? }, Component)`. The `children` object is simultaneously the declaration of which slots a component renders and the authorization — rendering an undeclared slot fails at load. Component props are the four derived shares: `PropsRuntime<K>` (standard hooks), `PropsRenderSlots<S>` (children keys), `PropsStore<H>` (store factory), plus the inject face. Five standing hook seats: `useSession`, `useSessions`, `useWorkspaces`, `useStore`, `renderSlot`. `dsh-ui-slots` provides the framework core: `SlotCore` registry with exclusive-ownership enforcement. `dsh-ui-primitives` provides Cordis-free React primitives styled through `--dsw-*` tokens. `dsh-ui-conversation` is the chat view domain: conversation node rendering, composer machine, and view tabs. `dsh-ui-layout` provides AppFrame with the four child slots. `dsh-client-locale` provides bilingual locale with typed `LocaleNamespaceMap` and revision-keyed bindings.

## Infrastructure utilities

`dsh-atomic-write` provides `writeFileAtomic` (random-suffix sibling, exclusive `wx` create, rename) and `withFileLock` (cross-process lock with exponential backoff). `dsh-timeout` provides `clampTimeout`, `Deadline` (dispose-once `using`), `IdleWatchdog` over async-iterator demands, and `MAX_TIMER_DELAY_MS`. `dsh-output-retention` provides `ItemRetainer` (ordered units, head-only) and `TextRetainer` (byte-oriented head/tail/headTail, UTF-8-boundary-safe). `dsh-launch-environment` provides an immutable launch-time environment snapshot layered `process > project-env > user-env` with provenance. `dsh-home-paths` provides `DSH_HOME` resolution and `expandHomePath`. `dsh-brand` is a type-only `Branded<B>` nominal typing primitive. `dsh-native-command` is a library for no-shell `execFile` with AbortSignal termination. `dsh-anonymous-user-id` derives a random UUID scoped to the harness home.

## Runtime invariants (`dsh-invariants`)

`InvariantRegistry` is a configurable registry for package-owned runtime invariant contributions. Patterns are compiled with allowlist-then-blocklist selection. Packages call `ctx.invariants.register(packageName, { install, inject? })`; the installer runs in a child fiber owned by the registration. The `verify-package-invariants` gate audits every companion: each must check an event/data relation or state a justified "No runtime invariant" reason.

## Test support

`dsh-acp-snapshot` provides the snapshot test harness: subprocess launcher, scripted scenario harness, pure normalizers, and the suite factory. `dsh-agent-loop-testkit` mounts the five prerequisite services (LlmRuntime, SessionStore, SystemPrompt, ToolRuntime, AgentRegistry) in order. `dsh-client-runtime` (test-support) provides a jsdom slot test runtime with real Cordis Context + production SlotRegistry + web-react renderer around test doubles. `dsh-llm-mock-server` is a scriptable OpenAI-compatible HTTP/SSE server with 24 behavior names. `dsh-llm-replay` is a keyless snapshot-test LLM adapter: `deriveReplayScript` builds a model-call script from `assistant/chunk` events. `dsh-loader-smoke` provides a subprocess harness for keyless example smokes with tsx source launch and isolated `DSH_HOME`.
