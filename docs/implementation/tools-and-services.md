## Skill registry (`dsh-skill`, `dsh-skill-filesystem`)

`SkillRegistry` stores registrations in the calling context's scope layer (`ScopedLayers`), so an agent preset's mounts bind to that scope. `collect` merges global + scope-chain layers with revision-keyed caching (bounded LRU, up to 2 retries against concurrent revision bumps). Candidate ranking: lower `rank` then registration order; nearest layer shadows outright. `registerProvider` returns the exact effect disposer. `dsh-skill-filesystem` is the local-filesystem provider: roots resolved as project `.dsh/skills` and `.agents/skills`, custom, user `~/.dsh/skills` and `~/.agents/skills`, and bundled, with ranks 100-600. Reads go through `ctx.fs` when present. `WatchManager` keeps refcounted root states with chokidar `awaitWriteFinish` stability and microtask-coalescing invalidation. `fs/observed` mutations from `edit`/`write` tools trigger invalidation when paths can be skills. `dsh-tool-skill` publishes a durable session skill catalog and provides the model-facing `skill` loader tool. The catalog waterfall compares SHA-256 digest of entries with the visible durable catalog history; a change publishes `<available_skills>` replacement. A `/name` gesture watermark in direct user text triggers deterministic instruction injection of `user-invocable` skills.

## Subagent delegation (`dsh-subagent`)

`SubagentRuntime` is the Service Definition: `start()` validates capabilities, resolves the durable descriptor, calls the provider, and wraps publication in a lifecycle observer. `SubagentContinuationManager` reserves child ids, materializes activations (child Agent + report tool contributions), and uses the agent inbox as the sole turn queue (FIFO). Continuable providers contribute only a detached creation spec (`prepareContinuable`). `dsh-subagent-in-process-driver` is the shared driver: `startInProcessRun` resolves child depth, options, and meta, captures delegated policy overrides before the first await, and runs `parent.ctx.agents.create()` with a setup that applies `appendDelegatedPolicyOverrides`, `applyChildComposition`, and structured runtime. `dsh-subagent-fork-in-process` seeds the child with the parent's completed-turn prefix sliced through the last `turn/end`. `dsh-subagent-spawn-in-process` starts a fresh child with no seed. `dsh-subagent-acp` spawns a child process over the ACP wire via `ctx.subprocess.spawn`; teardown is stdin EOF → `disposeEofGraceMs` → `terminate()` with whole-tree exit proof. `dsh-subagent-claude-code` spawns Claude Code via the official Agent SDK projected onto the subprocess seam. `dsh-subagent-codex` spawns a `codex app-server --stdio` process. `dsh-subagent-dsh-sdk` runs a complete dsh runtime as child over stdio JSON-RPC. `dsh-tool-subagent` is the model-facing delegation tool; `dsh-tool-subagent-control` provides `send_message`/`interrupt_agent`; `dsh-tool-subagent-report` installs a child-scoped `report` tool.

## Workflow engine (`dsh-workflow`, `dsh-workflow-worker-thread`)

`WorkflowEngine` is the abstract Service Definition. `WorkflowStopReason` is a closed union (`completed | cancelled | error`); `WorkflowError.fatal` drives combinator discipline: `parallel`/`pipeline` re-throw fatal errors and null out per-item failures. `dsh-workflow-worker-thread` is the default backend: a fresh worker runs model-written JS in an escapable vm. Host-side `WorkerRun.cancel` posts Cancel, aborts the canonical child signal, and arms an unref'd grace. Message admission closes on the first death signal. `AgentStart`/`AgentEnd` gate ensures exactly one end per started agent, with host-synthesized `cancelled` endings for stranded agents. Worker-side `WorkflowExecution` provides FIFO concurrency slots, total-agent cap, per-item caps, and hooks (`agent`, `parallel`, `pipeline`, `phase`, `log`); cancel makes every hook throw `CANCELLED` at the next boundary. `dsh-tool-workflow` is the model-facing tool; `dsh-tool-ralph` is a fixed Ralph-loop tool with bounded round handoff.

## Background jobs (`dsh-jobs`, `dsh-jobs-local`)

`JobRegistry` is the abstract Service Definition: `<kind>-N` ids, owned access fenced by the owner's session id, first-wins settlement, and contained `onJobDone` listeners after commit. `dsh-jobs-local` is the in-memory backend: `TrackedTask` records in a Map plus kind counters; scope-layered controllers, listeners, and changed-notifications over `ScopedLayers`. `settle` is first-wins; `disposeAll` closes listeners, cancels, force-fails orphan cancels, awaits settled tails, then removes effects. `dsh-tool-jobs` provides `job_output`/`job_list`/`job_kill` tools. `onJobDone` delivers unreported notices: wakeup → `owner.followup` while idle under `maxConsecutiveWakes`, else `owner.inject`; wakes reset on user-derived inbox claims.

## Goal tracking (`dsh-goal`, `dsh-goal-round-driver`)

`GoalService` is event-sourced: per-session `GoalCache` folds `goal/change` events incrementally. Mutations build full snapshots with monotonic revision, commit through `session.append` plus `sync` under a `pendingActivation` seq guard, then emit `goal/changed`. Activation (`armed`/`disarmed`) is process-local and reconstitutes as disarmed unless the pending activation seq matches. `dsh-goal-round-driver` drives automatic same-session continuation: `agent/status idle`, `goal/changed`, and inbox events trigger `drive`, which computes the next round and calls `ctx.goals.block` on exhausted round-limits or queue failures. `dsh-tool-goal` provides `get_goal`/`create_goal`/`update_goal` tools with authority policy (direct-human or goal-round); `blocked` succeeds only after `blockedAfterConsecutiveRounds`.

## Schedule (`dsh-schedule`)

Agent-scoped durable one-shot and fixed-rate reminders over the session log. The fold derives `FoldedSchedules` from `schedule/change` events (forks fold only from `seedLength`). `driveOnce` runs inside `runScheduleTransaction`; every durable decision resets the unref'd bounded timer. `dueDecision` derives latest occurrences without enumerating backlogs. Fixed-rate lower bound is `MIN_EVERY_INTERVAL_SECONDS = 300`. Dispatch uses `followup` then appends `schedule/change` dispatch events after synchronous enqueue. The runtime only attaches to future root agents, not existing or persisted ones.

## Web access (`dsh-web`, `dsh-web-fetch-http`, `dsh-web-search-*`)

`WebRuntime` is the Service Definition with separate search and fetch provider registries. Selection rules resolve at execution time from `available()` (never by registration order). `dsh-web-fetch-http` is the anonymous safe HTTP fetch provider: manual same-origin redirects revalidated per hop with hop budget, content-length pre-reject vs streaming byte-cap, and TextDecoder resolved before reading. `dsh-web-search-deepseek` dispatches one model inference per search through the DeepSeek API with the native `web_search_20250305` server tool. `dsh-web-search-exa` uses the Exa `/search` API. `dsh-web-search-perplexity` uses the Perplexity chat-completions endpoint. `dsh-tool-web` provides `web_search` and `web_fetch` tools; the fetch tool converts HTML to markdown via Turndown with a `MAX_CONVERSION_DEPTH = 512` guard against superlinear DOM walks.

## Attachment storage (`dsh-attachment`, `dsh-attachment-local`)

`AttachmentStore` is the abstract seam: `saveImages` enforces count, aggregate-bytes, and media-type checks, validates every input (full decode) before the first write, then saves in batch order. `dsh-attachment-local` stores under `DSH_HOME/attachments/v1`. Save flow: probe dimensions from fully decoded bytes, sha256 content addressing by 2-level prefix, staging plus `link` for dedup. Every ancestor directory up to the FS root is fsynced before the reference is visible. Default limits: 5 MB/image, 20 images, 100 MB batch, 40 MP.

## Message feedback (`dsh-message-feedback`, `dsh-command-feedback`)

`MessageFeedbackService` stores durable, versioned sidecar feedback (rating + note) for finalized assistant messages in the `message-feedback` storage domain. `put` runs full read/compare/write mutations serialized per session via `operationTails`, comparing `ifVersion` against the current row. Session ownership is guarded by persisted identity matching. `dsh-command-feedback` provides a human-facing `/feedback` command appending `feedback/record` log-only events.

## Spill policy (`dsh-spill`, `dsh-spill-local`, `dsh-spill-policy`)

`SpillStore` is the abstract seam: `saveText` persists full content verbatim. `dsh-spill-local` stores files under a private `0700` per-process tmpdir. `encodeSegment` is a lossless injective scheme (`~XXXX` escapes) for every UTF-16 string. `saveTextFile` opens `'wx'` `0600` with a random 6-byte prefix defeating symlink planting. `dsh-spill-policy` is a `tools/post-execute` transformer: when a final result's UTF-8 size exceeds `maxInlineBytes`, it saves the full text to a spill artifact and replaces the model-facing result with a bounded head/tail preview plus the locator and retrieval guidance. Both the model-facing arm and the `tools/code-dispatch-log` arm share one `spillReplacement` implementation. Failure semantics are best-effort: no session owner, no backend, or a `saveText` failure → warn and return the original inline result.
