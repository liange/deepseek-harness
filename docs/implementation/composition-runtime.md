# Composition and Runtime — Implementation

English | [中文](composition-runtime.zh.md)

How the boot process, profiles, bundles, agent presets, dynamic extensions, settings, credentials, hooks, and MCP client work internally. See [subsystems/settings.md](../subsystems/settings.md), [subsystems/credentials.md](../subsystems/credentials.md), and [subsystems/extensions.md](../subsystems/extensions.md) for type definitions.

## Boot process (`dsh-app-boot`, `dsh-cmdline`)

`boot()` creates a `Context`, sets `baseUrl` to the config directory, provides `dshHomePath`, awaits `ctx.plugin(Loader)`, mounts a pinned-id `'include'` root entry carrying all patch layers as one flattened list through `applyEntryPatches`, then settles and audits every entry fiber. `loadLayeredEnv` parses project and home `.env` layers with `parseEnv`, rejects bootstrap-only names, applies without replacing inherited values, and snapshots provenance. `renderConfigDump` re-runs the patch algorithm over prefix snapshots to compute per-row provenance YAML comments. `dsh-cmdline` provides the launcher→app command-line contract: `provideCmdline` freezes the argv snapshot and provides `ctx.cmdlineArgs` and `ctx.appExit`. `parseCmdline` reads them through the global store, applies `exitOverride()` plus `configureOutput` to every subcommand, and routes help, version, parse, and `program.error` rejections through `ctx.appExit` (never `process.exit`).

## Profiles and bundles (`dsh-base`, `dsh-headless`, `dsh-web-app`)

A profile is a named composition stored in the harness home. A bundle is a distribution format for Cordis config rows. `dsh-base` is the first layer of every profile: one `cordis.patch.yml` insert of 78 rows addressed by id (timer, hmr, llm, session, typert, session-title, agent, jobs, llm-retry, settings, credentials, sandbox + policy, bash/pwsh pairs, approval presets, tools, skills, commands, goal, plan-mode, compaction, subagent, workflow, todos, web-search, fs-sandbox, llm-deepseek). A patch REPLACES a row's whole config. `dsh-headless` overrides base rows for one-shot task mode: the runner awaits Loader settlement, creates an `Agent` with a fresh `SessionId`, sends the user message, waits `whenIdle()`, prints the final assistant text, and exits through `appExit`. `dsh-web-app` overrides base rows for the browser surface: inserts storage trio, webserver, api-gateway, cordis-host-runner, api-remotes, client module system, and the ui-* roster. The glue plugin samples LAN IPv4 once when bound to all interfaces, mounts `FrontendStatic`, registers the `app:web-surface` prompt section, and prints the URL line only after Loader settlement.

## Agent presets (`dsh-agent-presets`)

`AgentPresets` resolves roots from configured directories plus the home `~/.agent-presets`. `ensureStanding` single-flights a `Map<presetId, Promise>`: it stats the composition (mtimeMs+size stamp) before mounting, creates a `dsh-scope` scope off the untraced context, and `mountPreset`s a `PresetTree` Include into it. `mount.ts` overrides `import` to resolve bare specifiers from the recorded harness `baseUrl` and overrides `write()` to a no-op. It audits `inactiveRows` (pending injects) and `leakedServices` (root-realm publishes), and prunes dead mounts. Agents join via `bindScopeParent`; `composeFrom` joins a child to its parent's standing mount synchronously. `dsh-persona` is a scope-only row replacing the deployment persona inside one agent preset.

## Dynamic extensions (`dsh-cordis-host-runner`, `dsh-cordis-client-runner`)

`DynamicCordisRunner` is the host-side plugin system: immutable Packages (host+client source), per-Session Plugins, one active Run, and human-approved Client activation. `run()` resolves modal rules (`run` vs `update` against `currentPackageId`/`nextPackageId`), single-flights per-plugin activation. `startFresh` retracts the prior run, evaluates the host half in a `node:vm` sandbox (tagged console, `harness.handle/defineTool/registerTool`, encoding primitives, traps redirecting `require`/timers/`fetch` to services), and mounts the plugin as a child fiber under the `cordis-dynamic` group. `dsh-cordis-client-runner` is the browser half: each package's source runs as the body of an async function whose parameters are the symbol surface. The result is wrapped and seated as a factory in the module table, creating a real Loader entry. `dsh-tool-cordis` provides `cordis_inspect_*`/`cordis_define`/`cordis_run`/`cordis_stop`/`cordis_undefine` tools plus `@pluginId` context injection. `dsh-client-ui-cordis` provides the browser inventory panel, approval flow, and run card tools.

## Settings (`dsh-settings`, `dsh-settings-file`)

`SettingsProvider` is the Service Definition: `register(ns, schema, {base, applies, validate})` returns a `SettingsScope`. Resolution = `schema(mergeLayers(base, section))` (plain-objects merge recursively; arrays/scalars replace wholesale), deeply frozen. Writes: `cloneJsonShaped` rejects non-JSON-safe values; each namespace has a serialized write chain; `expectedRevision` check runs at queue front → `SettingsConflictError`; persist → commit. Commit fires only when `deepEqualJson` detects a change: per-watcher serialized invocation chains, then `settings/updated` fan-out. `dsh-settings-file` is the file-backed backend: one YAML/JSON document under `$DSH_HOME/settings.yaml`. `persistSection`: mkdir `0700` → `withFileLock` → `reconcileFromDisk` (folds in unobserved external edits) → render → `writeFileAtomic` `0600`. YAML rendering re-parses the cached text and applies `patchNode` leaf-level diffs so comments, anchors, and formatting survive. A chokidar watcher hot-reloads; an invalid reload keeps last-good sections.

## Credentials (`dsh-credentials`, `dsh-credentials-local`)

`CredentialProvider` is the abstract seam: `resolve` per call (consumers must not cache across operations), `describe` (source/writability without the value), `set`/`unset` (empty stored value is absent everywhere). `dsh-credentials-local` is the file-backed backend over `$DSH_HOME/.credentials.yaml`. Resolution order: inherited process env (wins, read-only) > managed file > project `.env` > home `.env`. `set`/`unset` first run `assertUnshadowed` (reject when the inherited environment supplies the ref), then a serialized op: `withFileLock` → `reconcileFromDisk` → comment-preserving single-key edit → `writeFileAtomic` `0600` → `notifyUpdated`. `assertOwnerOnly` refuses group/other permission bits (POSIX). A chokidar watcher hot-reloads; an invalid reload keeps the last snapshot.

## Hook bridges (`dsh-hook-protocol`, `dsh-hooks-claude-code`, `dsh-hooks-codex`)

`dsh-hook-protocol` is the shared non-plugin library: `runHook` executes through `ctx.shell.run()` with JSON stdin, per-hook `timeoutSec`, and the owning-operation signal. `parseHookOutput`: exit 2 = block with stderr reason; on exit 0, `{`-prefixed stdout is parsed for `continue`/`stopReason`/`systemMessage`/`decision` plus `hookSpecificOutput`. `mergeHookOutputs` folds `deny > ask > allow`. `dsh-hooks-claude-code` parses `hooks.json` once at load and maps points onto waterfall extension points: `agent/session-start`, `agent/pre-step` (deny → reject), `tools/pre-execute` (deny/ask), `tools/post-execute` (deny → block), `agent/turn-stopping` (deny → steer), `subagent/start|end`. `dsh-hooks-codex` mirrors the CC bridge with Codex's contract differences: five points, regex-only matchers, `permission_mode: 'default'`, and `plainStdoutAsContext: true` on SessionStart and UserPromptSubmit.

## MCP client (`dsh-mcp-client`)

Each instance reserves its `serverName` in a root-keyed WeakMap set. The supervisor owns client and transport generations: each generation is a fresh MCP SDK `Client` plus transport (stdio spawns with `scrubbedParentEnv()`; streamable HTTP takes URL+headers). Initial connect + tool sync settles `ready` for plugin activation. `ToolListChangedNotification` triggers re-syncs serialized on one `syncChain`. Reconnect uses doubled backoff per outage; an uptime ≥ `maxDelayMs` resets the budget; exhaustion unregisters tools and stops. `dispose` closes the live client, waits `settling` + `syncChain`, and unregisters everything. Registered tools are prefixed `mcp__<serverName>__<rawName>`.
